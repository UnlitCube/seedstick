# サンプルのプロファイル

GUI の「プロファイルを開く」からそのまま読める JSON を置いてある。

**インストーラ版には同梱される。** 配布物の `resources\samples\` に入る。

| 形態 | サンプルの場所 |
|---|---|
| インストーラ版 | インストール先の `resources\samples\`（既定は `%LOCALAPPDATA%\Programs\Seedstick\`。インストール時に変更できる） |
| portable 版 | **実行のたびに一時ディレクトリへ展開されるので、置き場所として当てにしない** |
| このリポジトリ | `samples/` |

GUI の「プロファイルを開く」でそのパスの JSON を指定する。
portable 版を使うなら、このリポジトリから JSON をコピーしておくのが確実。

**どれも `npm run test:unit` が読み込んで検証しているので、壊れたまま残ることはない**
（`packages/shared/src/autoinstall/samples.test.ts`）。

| ファイル | 内容 |
|---|---|
| [`ip-only.json`](ip-only.json) | **IP だけを起動メニューで切り替える。** ホスト名・ユーザー・ディスクは全台同じ |

## `ip-only.json` — IP だけ別

同じ構成のマシンを何台も作るが、**IP アドレスだけが台ごとに違う**という構成。
1 本の USB を作れば、起動時に GRUB のメニューでその台の IP を選べる。

### 何が固定で、何が起動時に決まるか

| 項目 | 扱い |
|---|---|
| ホスト名 (`ubuntu-node`) | **固定**。全台同じ |
| ユーザー (`sysop`) | **固定**。全台同じ |
| インストール先ディスク | **固定**（いちばん大きいディスク） |
| **IPv4 アドレス** | **起動メニューで選ぶ** |
| ゲートウェイ・DNS | 全台同じ値を、選んだときに一緒に渡す |

### 起動メニューに出る項目

```
Try or Install Ubuntu Server [Autoinstall]   ← 何も選ばないとこれ（予備の 10.0.2.90/24）
ip-100 - 10.0.2.100/24
ip-101 - 10.0.2.101/24
ip-102 - 10.0.2.102/24
Enter values manually                        ← インストーラの画面で手入力する
```

**先頭は「元の項目」のまま**にしてある。ホストの項目を先頭に置くと、
タイムアウトまで放置しただけで全台が同じ IP を掴む（`CLAUDE.md` の落とし穴 51 / 27）。

先頭の項目で入ると**予備の `10.0.2.90/24`** が使われる。
本番で使う値にしていないので、**選び忘れた台がすぐ分かる**。

### 使う前に必ず変えるところ

1. **パスワード。** サンプルは空にしてある（ハッシュを入れて配ると、そのまま使う人が出る）。
   GUI が「パスワードを設定してください」と 1 件だけ error を出すので、そこで設定する。
2. **IP アドレス。** `10.0.2.x` は **QEMU の user-mode ネットワーク**の値で、
   このサンプルをそのまま VM で確かめられるようにしてある
   （ゲートウェイ `10.0.2.2`、DNS `10.0.2.3` は QEMU が用意するもの）。
   実環境では自分のサブネットに置き換える。
3. **台数。** プリセットは 3 件だけ。GUI で増やせる。
   ただし **grub.cfg は 2048 バイトに収まる必要がある**ので、
   増やしすぎると「入りきらない」と検証が止める。

### ホスト名も台ごとに変えたいとき

「実行時に決める値」の**ホスト名**も「起動メニュー」に切り替え、
各プリセットの `hostname` を埋める。そうすると menuentry の引数に
`ai.hostname=` が増える。

## VM で確かめる

```
npm run e2e:vm:ip
```

WSL2 + QEMU で、**このサンプルそのもの**（`samples/ip-only.json`）から USB イメージを作り、
**起動メニューの 2 番目のプリセット (`ip-101`) を選んだことにして**無人インストールを完走させ、
インストールされたシステムに `10.0.2.101/24` が入っていることを確かめる。

確かめているのは次の連鎖:

```
GRUB のメニュー項目のカーネル引数 (ai.ipv4=10.0.2.101/24)
  → early-commands の python が /proc/cmdline から読む
  → /autoinstall.yaml を PyYAML で書き換える
  → subiquity がそれを適用する
  → cloud-init が /etc/netplan に書き出す
```

**予備の `10.0.2.90/24` と、選ばなかった `10.0.2.100` / `10.0.2.102` が
入っていないこと**も一緒に見ている（「たまたま何か入っていた」を排除するため）。

> **VM のときだけ `set default=<n>` を入れて「選んだことにする」。**
> GRUB のメニューはシリアルにも出るので矢印キーで選ぶこともできるが、
> それは「メニューが出るまで何秒待つか」に依存する——負荷で描画が遅れると
> 静かに別の項目を選ぶ。既定を書けば決定的になる。
> **これは検証のためだけの仕掛けで、実 USB に焼くときは入らない**
> （`console=ttyS0` を VM だけが足すのと同じ。落とし穴 105）。
